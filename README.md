# ✨ 拾光造梦局 | The Museum of Lost Light

> **在世界睡着以后，替它找回遗失的光。**
>
> *When the world falls asleep, bring back the light it has forgotten.*

一款融合 **艺术美学、情感叙事、光影交互与轻度解谜** 的独立网页游戏。

在永不天亮的世界里，经营一座漂浮于夜空中的记忆博物馆，收集被遗忘的光，修复失落的回忆，并决定世界是否应该重新迎来黎明。

**项目状态：** 设计阶段 / 开发准备中

**游戏类型：** 叙事解谜 · 互动艺术 · 治愈系独立游戏

**目标平台：** Web Browser（桌面优先，兼容移动端）

**技术栈：** HTML5 · CSS3 · JavaScript · Canvas 2D · Web Audio API

**核心特色：** 单 HTML 文件 · 无需安装 · 离线运行 · 程序化视觉效果

---

## 📖 游戏简介

世界停在了清晨 **05:20**。

那一天，太阳没有升起。

街灯忘记如何发光，花朵忘记如何绽放，鸟儿忘记清晨的旋律。随着时间逐渐停滞，人们珍贵的记忆也开始消散。

为了保存这些即将消失的光，一座名为「拾光造梦局」的玻璃博物馆出现在夜空之上。

你将扮演博物馆最后一位 **拾光者（Lightkeeper）**，在神秘光灵「小光（Lumi）」的陪伴下，探索不同的记忆空间，修复失去光芒的藏品，收集五颗散落的晨星。

然而，随着黎明逐渐临近，你将发现一个隐藏的秘密：

**并不是太阳拒绝升起，而是博物馆一直在阻止时间前进。**

当世界重新迎来黎明，博物馆和其中保存的记忆也将面临消失。

最终，你需要作出选择：

**让黎明到来，还是让美好的回忆永远停留在夜晚？**

## 🌌 核心特色

### 🎨 1. 沉浸式艺术视觉

采用极简插画、柔和光影与程序化动画相结合的美术风格。

- 午夜蓝、琥珀金与月光白构成主视觉体系。
- 动态星空、流动星尘、玻璃反射与粒子光效。
- 鼠标移动产生金色光轨与柔和交互反馈。
- 随着游戏进度，天空逐渐从深夜转向黎明。
- 场景中的光照、色彩与音乐随玩家行为动态变化。

游戏力求让每一个场景都像一幅可以交互的数字艺术作品。

### 🧩 2. 多样化轻度解谜

游戏围绕「光、记忆、时间、声音」设计不同的谜题机制。

| 解谜机制 | 玩家操作 | 游戏目标 |
|---|---|---|
| 光线反射 | 拖动与旋转镜子 | 将光线引导至目标 |
| 记忆捕捉 | 绘制鼠标轨迹 | 收集游离的光粒子 |
| 时间回溯 | 拖动时间轴 | 观察过去并改变事件 |
| 音乐解谜 | 点击玻璃音铃 | 重现隐藏的旋律 |
| 综合谜题 | 组合多种操作 | 修复最后一颗晨星 |

没有战斗、血条或复杂的操作系统。

游戏的乐趣来自探索、发现，以及每一次成功修复记忆所带来的满足感。

### 🦋 3. 光灵伙伴 Lumi

玩家将拥有一位名叫 **小光（Lumi）** 的神秘伙伴。

它是一只由晨光构成的发光生物，拥有半透明的翅膀。

小光会：

- 跟随玩家的鼠标移动。
- 对不同物品产生好奇反应。
- 在玩家遇到困难时提供轻微提示。
- 在解谜成功时围绕玩家飞舞。
- 随着剧情推进逐渐揭示自己的秘密。

小光不仅是引导角色，也是整个故事的重要组成部分。

### 🕰️ 4. 动态世界时间

游戏内存在一座巨大的天文钟。

随着玩家收集晨星，世界时间逐渐向 **05:20** 推进。

时间的变化会影响整个博物馆的环境，包括天空颜色、环境光照、背景音乐和藏品状态。

05:20 既象征黎明将至，也隐含着关于爱、记忆与告别的情感主题。

### 💌 5. 记忆收藏与隐藏彩蛋

修复完成的物品会成为博物馆中的永久藏品。

每件藏品都拥有独立的视觉效果和简短故事，并能对博物馆环境产生影响。

计划加入以下探索内容：

- 自由连接星星，绘制隐藏星座。
- 在不同顺序下触发特殊物品对白。
- 鼠标静止时出现隐藏光蝶。
- 收集带有诗句的记忆明信片。
- 将游戏中的记忆场景导出为 PNG 图片。

## 🗺️ 游戏章节

游戏计划包含一个序章、五个主要解谜章节和一个终章。

### 序章：午夜来信

*Prologue — A Letter at Midnight*

玩家在一座陌生的玻璃博物馆中醒来。

周围是漆黑的星空，只有一只微弱发光的生物在空中飞舞。

在小光的引导下，玩家学习基础交互，发现博物馆中的天文钟，并收到一封神秘来信：

> 「请在黎明到来之前，找回那些被遗忘的光。」

### 第一章：最后一盏路灯

*Chapter I — The Last Streetlight*

一条被黑暗吞没的街道，一盏失去光芒的路灯。

玩家需要旋转不同位置的镜子，利用光线反射，将遥远的月光引导至灯芯。

当路灯重新点亮，沉睡的街道逐渐显现。

**核心机制：** 二维光线反射与空间解谜。

### 第二章：装着夏天的瓶子

*Chapter II — Summer in a Bottle*

一只透明玻璃瓶中，曾经保存着整个夏天。

如今萤火虫四散，瓶中的森林逐渐枯萎。

玩家需要绘制发光轨迹，引导游离的光粒子回到瓶中。

当最后一只萤火虫归来，微缩的夏日森林重新出现。

**核心机制：** 粒子捕捉与轨迹绘制。

### 第三章：清晨五点二十分

*Chapter III — 05:20, Before the World Wakes*

一间停留在黎明前的旧卧室。

破碎的茶杯、未寄出的信、枯萎的植物，以及一座永远停在 05:20 的时钟。

玩家通过拖动时间轴，观察不同时刻的房间状态，并在正确的时间节点干预事件。

这一章将首次揭示世界停滞的原因。

**核心机制：** 时间回溯、事件观察与因果解谜。

### 第四章：不会唱歌的花

*Chapter IV — The Flower That Forgot Its Song*

一朵透明的花被封存在玻璃罩中。

它已经忘记了曾经属于自己的旋律。

玩家需要观察花瓣闪烁的顺序，敲击不同音高的玻璃音铃，重新演奏记忆中的音乐。

当旋律完整响起，花朵重新绽放。

**核心机制：** 音乐记忆与节奏解谜。

### 第五章：最后一颗晨星

*Chapter V — The Last Morning Star*

博物馆最深处，巨大的晨星正在逐渐失去光芒。

玩家需要综合运用之前掌握的光线反射、粒子收集、时间回溯与音乐交互能力，完成最终的修复仪式。

五颗晨星重新汇聚，世界时间抵达 05:20。

**核心机制：** 多机制组合解谜。

### 终章：日出之前

*Epilogue — Before Sunrise*

博物馆的穹顶缓缓打开。

玩家终于得知，小光是博物馆保存的第一束晨光。

如果释放晨星，太阳将重新升起，但博物馆也将消失。

如果保留晨星，博物馆与小光将继续存在，而世界将永远停留在黎明之前。

玩家需要作出最终选择。

**结局 A：让黎明到来**

> 「告别不是失去，而是让光继续旅行。」

**结局 B：留住这片星空**

> 「有些星星很美，只因为我们还没有学会告别。」

游戏不对两种选择作出简单的对错评价。

## 🎮 操作说明

以下为计划采用的操作方式：

| 操作 | 功能 |
|---|---|
| 鼠标移动 | 控制光标与小光 |
| 鼠标左键 | 点击物品、确认交互 |
| 鼠标拖动 | 移动物品、绘制轨迹 |
| 鼠标滚轮 | 在支持的场景中调整观察范围 |

## 🛠️ 技术架构

本项目计划使用原生 Web 技术实现，不依赖大型游戏引擎。

### 技术选型

| 技术 | 用途 |
|---|---|
| HTML5 | 游戏页面与基本结构 |
| CSS3 | UI 样式、布局及过渡动画 |
| JavaScript (ES6+) | 游戏逻辑、事件管理和状态控制 |
| Canvas 2D API | 场景绘制、光线与粒子渲染 |
| Web Audio API | 程序化音效与环境音乐 |
| LocalStorage | 本地游戏进度保存 |
| RequestAnimationFrame | 动画循环与帧更新 |

### 系统设计

游戏计划采用模块化架构，主要包括：

- **Game Core：** 游戏主循环、状态管理与场景切换。
- **Scene Manager：** 关卡加载、场景渲染与过渡。
- **Input Manager：** 鼠标、键盘及触摸事件处理。
- **Particle System：** 星尘、萤火虫、光晕等粒子效果。
- **Lighting System：** 光线传播、反射及目标检测。
- **Audio Engine：** 合成音效与动态背景音乐。
- **Puzzle System：** 各章节谜题逻辑与通关判断。
- **Save Manager：** 游戏进度、收藏品和设置持久化。

### 单文件设计

项目的目标是将全部运行代码与必要资源整合为一个独立的 `index.html` 文件。

这意味着：

- 无需安装额外依赖。
- 无需配置服务器。
- 无需连接互联网。
- 无需下载外部图片或音频。
- 可通过浏览器直接打开运行。
- 方便通过 GitHub Pages 进行在线部署。

在开发过程中可以采用模块化源代码组织，最终再打包为单个 HTML 文件。

## 🚀 运行方式

### 本地运行

1. 下载项目发布的 `index.html`。
2. 使用 Chrome、Edge 或 Firefox 等现代浏览器打开。
3. 点击「进入博物馆」开始游戏。

### GitHub Pages 部署

项目完成后，可通过 GitHub Pages 免费部署。

1. Fork 或克隆本仓库。
2. 确保发布目录中存在 `index.html`。
3. 进入仓库的 `Settings → Pages`。
4. 选择对应分支及部署目录。
5. 保存设置并等待部署完成。

部署完成后，即可通过 GitHub Pages 提供的链接访问游戏。

## 🎨 美术设计

游戏采用统一的低饱和度夜间配色。

| 颜色 | 色值 | 主要用途 |
|---|---|---|
| 午夜蓝 | `#0B1020` | 主背景 |
| 雾霭蓝 | `#192C43` | 场景层次 |
| 琥珀金 | `#D8A96B` | 光线与交互 |
| 月光白 | `#E9E4D9` | 文字与高光 |
| 星尘灰 | `#8B9FAE` | 次要元素 |

设计关键词：

**Minimalist / Dreamlike / Atmospheric / Poetic / Interactive Art**

视觉上强调留白、柔和发光、缓慢运动与精细交互，避免过度复杂的界面和强烈的视觉噪声。

---

## 🎵 音频设计

游戏计划使用 Web Audio API 合成音效，以保持单文件与离线运行特性。

主要音效包括：

- 玻璃音铃与清脆点击声。
- 星尘收集时的短促音阶。
- 光线激活时的柔和共鸣。
- 解谜完成时的琶音。
- 随世界时间变化的氛围音乐。
- 最终黎明场景中的完整主题旋律。

音乐设计强调克制与空间感，让声音成为游戏叙事的一部分。

## 💡 设计理念

《拾光造梦局》希望探索三个问题：

**记忆是否一定需要被永远保存？**

**失去是否意味着美好的终结？**

**如果能够让时间停止，我们真的愿意永远停留在过去吗？**

游戏希望通过简单的交互、温柔的视觉语言和富有情绪的音乐，让玩家在解谜之外，获得一段值得回味的体验。

这里没有需要打败的敌人。

没有必须争取的最高分。

也没有唯一正确的结局。

只有光、记忆，以及你愿意如何面对即将到来的黎明。
